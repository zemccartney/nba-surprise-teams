# Supporting-font experiment: Nanum Gothic Coding

## Decision

Replace Iosevka Curly with Fontsource Nanum Gothic Coding's Latin 400/700
faces. Zack approved Nanum's appearance and observed faster loading in the
local Stats comparison. Victor Mono, Fira Code, Montserrat and M PLUS 1 Code
were also tried; none received final visual approval. No Astro Fonts API
migration, preloading, CSS-inlining change or custom font build was needed.

The source integration retains `font-display: swap`, sizes and weight
assignments. Font synthesis is disabled for chart, popover and code text.
Assets come from `@fontsource/nanum-gothic-coding@5.3.0`, with its OFL license;
explicit `latin-400.css` and `latin-700.css` imports avoid the Korean subsets.
The lockfile makes the selected assets reproducible.

## Observations, not universal guarantees

In the local Chrome comparison, the initial Stats chart requested only the
bold monospace face. Iosevka's WOFF2 body was 989,740 bytes; Nanum's was 14,448
bytes (14,748 bytes including the transfer overhead reported by Chrome).
Opening a tooltip also loads regular: the two Nanum WOFF2 bodies total
28,684 bytes, versus 1,972,808 bytes for the existing Iosevka pair: about a
98.5% reduction. Other site fonts remain unchanged.

The baseline `# Surprises` label changed from approximately 132px to 110px
in sampled animation frames. Nanum rendered at 110px with no captured width
transition in one normal and one throttled run. The throttled comparison
used 150ms latency and 200,000 bytes/s download, desktop 1440x1000, with no
CPU throttling. Zack approved the observed loading behavior and appearance.
This does not prove swapping is invisible on all devices/connections or
establish a Lighthouse/whole-page speed improvement. The strategy still swaps.

## Character coverage: accepted limitation

Both actual Latin WOFF2 character maps covered all strings found in 274 JSON
payloads across 270 built pages, plus the en/em dashes generated by Showdown
formatters. Rendered Stats chart labels were checked too. This is a current
content check, not a promise about every future name or symbol.

The files lack accented letters such as `é` and `ñ`, and mathematical minus
`−`. Current chart negatives use the supported ASCII hyphen `-`. A deliberate
browser probe confirmed fallback to Courier for `é −` on this machine. Zack
explicitly accepted these fallback limitations before integration. Recheck
coverage when adding new names, locales or symbols; CSS unicode ranges alone
do not prove a glyph exists.

## Repeat the focused check

Serve a fresh static client build with the existing harness, then run:

```sh
node plan/baseline/serve-static-gzip.mjs /path/to/build/client 4387
node plan/baseline/font-loading.mjs http://127.0.0.1:4387
```

The browser check covers `/stats/` and `/2025/CHA/`, light/dark themes,
390/1440px widths and normal/held/blocked font requests. It checks keyboard
point navigation, pin/dismiss, real loaded 400/700 faces, synthesis disabled,
page overflow, JS errors and a 60KB total font-body budget after opening a
tooltip. The budget failed on the original baseline at 1,986,444 bytes
(including the other site fonts), and passes with Nanum. It is deliberately
not a broad performance platform or a replacement for visual approval.

Local comparison builds omitted Sentry's build integration and blocked
external requests. The static server disables caching; these checks do not
measure warm-navigation caching, deployed/CDN behavior or every browser.
No deployment was performed as part of this experiment.
