A healthy dependency stance

Minimize unnecessary dependencies, not updates at all costs. Freezing indefinitely accumulates known vulnerabilities and makes eventual upgrades larger. Unreviewed constant churn increases exposure to new releases. Prefer a small justified dependency set, frozen reproducible installs, the existing release cooldown/provenance/build-script controls, small scheduled updates and prompt triage of relevant security fixes. A cooldown exception for an urgent fix should be deliberate and recorded.

Audit detects known advisories, not arbitrary malicious code. Fewer dependencies is useful, but rewriting mature security-sensitive code yourself is not automatically safer. Dev tools matter because they execute on your machine and in CI; CSP does not protect build credentials.

Automation proposal: choose one update bot—Renovate or Dependabot—not both. Start with a weekly update window, at most two open routine PRs, separated major upgrades, and no initial automerge. Confirm vulnerability coverage for the actual lockfile; use a scheduled full-graph audit report where needed. Security notifications should not wait for routine batching. New alerts should reach one inbox, not three dashboards.

Done: Zack can explain the main risks, an alert route is tested, current policy is documented, exceptions name an advisory/reason/review date, and CSP has a recorded outcome. Existing build gates still block what the policy says they block; an audit service outage is not a clean report.

What “a good spot” looks like

  • Season changes have a short runbook and reminders; no unknown critical correctness/security problem is being hidden in “later.”
  • The key architecture and workarounds are understandable, with a small evidence trail rather than a pile of unexplained generated code.
  • Dependency alerts arrive without remembering to run an audit; routine updates are small and reviewable.
  • Important regressions have a compact preflight, and its warnings lead to decisions rather than noise.
  • A normal week needs a small maintenance check—not a new infrastructure project. An empty active queue is a healthy outcome.
