Orientation for whoever picks this up

Keep this board current. When a round lands, flip its box, add the log.md entry and the review.md section. When a decision gets made, move the item out of the blocked state and record the outcome.

Working agreements

  • Address him as Zack. Push back with specific technical reasons; say so when it is a gut feeling. Never "you're absolutely right." Ask rather than assume.
  • Each round: its own branch stacked on the previous one, a log.md entry, and a review.md section — files to read in order, surprises, decisions you may flip, manual checklist, comparison artifacts.
  • Mechanical rounds get batched and reviewed at the end. Stop before anything that needs design input or his Cloudflare account.
  • Nothing may be created in the Cloudflare account without asking.
  • Decisions that fall out of a round get listed as "decisions you may flip" rather than asked one at a time.
  • A round is not verified until the dev server has been exercised, not just the built output.

eval "$(fnm env)"; fnm use >/dev/null; export PATH="$HOME/Library/pnpm:$PATH"

Verification harness · plan/baseline/

  1. pnpm run build, then serve with serve-dist.mjs — or astro preview when server islands are in play, which runs real workerd.
  2. capture.mjs to screenshot, compare.mjs against a prior run in runs/, interact.mjs for popovers and charts.
  3. dev-smoke.mjs --base <url> against a running dev server. Required for any round touching dev, the adapter, images, or middleware.
  4. pnpm run check and pnpm test.

    Four chart regressions against production — Zack, 2026-09-11

    All four come out of Step 4 (Recharts → ECharts), not the Astro or image work. Detail and starting hypotheses are under Issues found in review in the Step 4 section of review.md.

  • [x]

    Image handling — Step 9, branch svg-images

    Settled by dropping <Image> and getImage() entirely. Every asset on the site is an SVG, and no image service was doing anything to them but copying bytes. logo.astro and result-emoji.astro render a plain <img src={meta.src}>; the six chart call sites read .src off the imported metadata.

    Results: 98 → 45 emitted SVGs, 260,103 → 78,211 bytes, zero /_image requests in build, dev, or the two server islands. The Step 8 dev shim is deleted — it was dead code once nothing asked for /_image.

    Verified: 44/44 and 8/8 screenshots pixel-identical, dev-smoke.mjs 47 images 0 problems, island checked on real workerd.

    The general fix — never having to know an asset's type to know which component to use — is the image service, now specced in image-service-spec.html and tracked in section 5.

  • [x]

    svgo at build — Step 9

    Landed as an astro:build:done integration in svg-optimizer/ rather than a one-time pass over the sources, so the checked-in files stay readable. 46/46 files, 114.3 KB → 78.8 KB (31.0%), including public/favicon.svg.

    Left at svgo's default floatPrecision: 3, which moves antialiasing by 1–5 pixels on 21 of 44 screenshots (0.00% each). Precision 5 removes that and costs back ~11 KB — a one-line flip if the diffs bother you.

  • [ ]

    The ECharts chart symbols come from getImage() and are not <img>, so the check would not have caught them breaking. Worth fixing regardless of the image decision.

Infrastructure and deferred rounds

0 / 9 done
  • [ ]

    Custom image service — see image-service-spec.html

    A reusable Astro image service for Zack's Cloudflare-hosted sites: sharp at build, jimp + wasm codecs at runtime in workerd, SVG passed through as one file with no variants, and an svg-hush-based audit that fails the build on unsafe features that are not allow-listed. No dependency on Cloudflare's paid transformation product.

    This site is the test case, not the customer — Step 9 already removed its need for one. Every load-bearing claim in the spec is tagged VERIFIED with a file:line, UNVERIFIED, or ZACK DECIDES; read the open questions first.

  • [!]

    Content Security Policy

    Held deliberately for a session Zack and I do together — he wants to understand Astro's implementation, not just have one.

    Going in: security.csp emits a <meta> policy with hashes for Astro-processed scripts and styles, it is not applied in dev, external scripts and styles need hashes added by hand (Cloudflare's injected beacon is exactly that case), and 7.1 added kind scoping so inline style attributes can be allowed without loosening <style>.

  • [ ]

    Sentry rework

    Zack's standing worry is silently breaking it. Carries three items from above: disabling the middleware in dev, the globalThis.process banner in astro.config.mjs, and the CF_VERSION_METADATA binding (adapter 14.2.5), which is how Sentry detects releases and also adds a version cache tag and weak ETag.

  • [!]

    Needs his Cloudflare account. Blockers, all deliberate: wrangler.jsonc has the placeholder REPLACE_WITH_REAL_KV_ID; .github/workflows/deploy.yml is written, SHA-pinned and zizmor-clean but gated off behind vars.DEPLOY_ENABLED == 'true'; the custom domain has to move.
