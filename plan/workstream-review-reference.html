4. Pull a small amount of observability work forward

“Learn observability” is too broad for that weekend. Start with:

Can I tell whether users are seeing correct, fresh data, and explain why not?

You already have:

  • Worker observability enabled.
  • Sentry browser and Worker integration.
  • Release association and source-map handling.
  • 10% performance-trace sampling.
  • Reporting of live refresh failures, including failures hidden from users by successful stale fallback.

Before the game, locate those existing views. Useful questions:

  • Are upstream requests succeeding, and how long do they take?
  • Did a response come from fresh KV, an upstream refresh, or stale fallback?
  • How old is the served data?
  • Which release produced an error?

HTTP 200 is insufficient: stale fallback preserves availability while freshness can degrade.

6. Improve reset, but keep the solution small

Deleting an open DB is unsafe because an existing connection may retain the old file handle while new connections open a replacement at the same pathname. SQLite locking does not prevent filesystem unlinking; WAL/journal files complicate it further.

A sensible reset process:

  1. Require the app and DB clients to be stopped.
  2. Restore and validate the canonical dump into a temporary DB.
  3. Only after success, replace the working DB.
  4. Send the refresh notification afterward.
  5. Optionally retain one backup.

That catches missing/unreadable dumps, malformed SQL, incompatible schemas, validation failures and disk-space problems before destroying the current workspace.

An open-file check is a useful warning, not a race-proof guarantee. Explicitly treating reset as a maintenance operation matters more than elaborate detection.

7. Dependency security: audit isn’t the entire defense

For temporary exceptions, record:

  • Advisory ID—not a blanket package exclusion.
  • Affected version and relevant execution path.
  • Why it is temporarily acceptable.
  • Review/expiry date and upstream fix to watch.

Keep a full-graph report visible even if your deployment-blocking policy remains narrower.

Two important additions:

  • Malicious code or exfiltration may have no published advisory. Auditing doesn’t replace provenance, dependency review and least-privilege credentials.
  • Deployment/upload secrets are currently exposed at the workflow’s job level, including installation steps. Narrowing their availability is a concrete supply-chain hardening opportunity.

For bundle inspection, use bundler/module or source-map information to understand what ships, then investigate vulnerable paths. The existing artifact audit checks things such as SQLite leakage and artifact integrity; it isn’t a bundled-code vulnerability scanner.

8. Quick answers to the learning/code-review items

  • Is mise used in Actions? Yes. jdx/mise-action installs the locked tools, then the workflow invokes package scripts.
  • Package scripts versus mise? Consolidate implementations and policy, not necessarily the interfaces. Thin wrappers are fine.
  • Local Actions? act exists, but won’t reproduce hosted permissions, secrets or network origin exactly. For manually deploying through existing safeguards, the workflow already supports remote manual dispatch through GitHub CLI.
  • Browser usage here? I used Playwright through Node scripts in plan/baseline/, plus temporary Chrome DevTools Protocol scripts—not Chrome DevTools MCP or Puppeteer.
  • Showdown component pattern? Your observation is fair: archive/live dispatch lives in the route rather than an index.astro facade like standings/team stats. Shared presentation still exists. Worth reviewing for consistency, but not inherently a correctness problem.
  • Venue backfill review? Focus on source disagreements, stable IDs/scores, transactional writes and evidence for the exceptional box-score fallback—not merely the SQL diff’s size.

A guided architecture tour could follow two concrete journeys:

  1. Edit odds → dump → build → deploy.
  2. Page request → action → KV/upstream → rendered result.

That will probably teach you more than reviewing every file sequentially.
